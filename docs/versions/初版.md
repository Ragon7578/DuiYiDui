# 初版（基本功能 · 获客优先 · 尽快上线）

| 项 | 内容 |
|----|------|
| **版本名** | 初版 / Initial |
| **目标** | 尽快上线，吸引相关用户使用，并**持续收集反馈** |
| **范围** | **基本功能**即可 |
| **盈利** | **不需要**实际盈利点 |
| **上线策略** | **Web 先上**（约 8～12 周达反馈标准）；App 反馈后再加 |
| **计划** | **[roadmap/fast-launch.md](../roadmap/fast-launch.md)**（当前执行） |
| **功能细则** | [features.md](../features.md) · [design.md](../design.md) |

---

## 1. 两级上线标准

### 1.1 反馈上线（第一优先）

公网 Web 可访问，主闭环可走通，有反馈入口。完整清单见 [fast-launch §0.1](../roadmap/fast-launch.md)。

**达到即开始收使用反馈** —— 不以 App 商店为前提。

### 1.2 初版完整（第二优先）

在反馈迭代同时/之后：Android、iOS 覆盖同一套基本能力并上架。仍无盈利。

---

## 2. 初版要做什么

### 2.1 基本功能（Must）

| 模块 | 做到什么算够 |
|------|----------------|
| 账号 | 注册登录；可补邮箱；忘记密码可用（可先简后补） |
| 目标 | 创建（**奖励必填**）→ 进度 → 达成 → **标记奖励已兑现** |
| 待兑现 | 首页 / 列表能发现 |
| 见证人 | 轻量邀请约 1 人（不强制） |
| 契约 | 基础约定与条款（可简化） |
| 信任分 | 中性展示 |
| 通知 | 站内基础通知 |
| 反馈 | **产品内可提交意见**（上线必有） |
| 多端 | Web 先；App 后 |

### 2.2 初版明确不做

| 类别 | 内容 | 归入 |
|------|------|------|
| 盈利 | 会员、内购、广告、品牌券 | [终极版](./终极版.md) |
| 重功能 | 押金、公益池、积分商城、徽章墙 | 终极版 |
| 重社交 | 公开围观、连坐默认开 | 终极版 |
| 体验膨胀 | Todo 化标签/看板 | 不做 |
| 挡反馈 | 「必须先上架 App 再收反馈」 | 不做 |

语音 / AI：可选项，不可用时须能手动完成。

---

## 3. 上线后看什么（使用反馈，非收入）

| 指标 | 建议观察 | 用途 |
|------|----------|------|
| 7 日内创建带奖励目标 | ≥40% | 故事是否看懂 |
| 达成者中已兑现 | ≥30% | 差异化是否被用 |
| 曾邀见证人 | ≥15% | 社交约束 |
| D7 留存 | ≥20%（可调） | 是否值得开 App / 扩功能 |
| 反馈条数与主题 | 每周汇总 | 驱动下 Sprint |

未达标：改引导与主路径，不上盈利、不堆终极版。

---

## 4. 获客话术

- 「把要对得起自己的事写下来，想好奖励，做到了真去兑现。」  
- 「可以请一个在乎你的人当见证人。」  
- 「信用看得见——不是羞辱，是履约档案。」  
- 「初版上线，欢迎直接提意见。」  

避免：会员、押金、品牌券。

---

## 5. 与试验版、终极版

| | 试验版 | **初版（反馈上线）** | 初版完整 | 终极版 |
|--|--------|----------------------|----------|--------|
| 目标 | 可演示 | **公网可用 + 收反馈** | 含 App | 全集+盈利 |
| 周期 | 已有 | **约 8～12 周** | 反馈后滚动 | 更后 |

开发默认只跟 [fast-launch.md](../roadmap/fast-launch.md)，直到评审进入终极版。
