## 1. 两条轨道

```
试验版
   │
   ├────────【快速轨 · 当前默认】────────┐
   │  F0→F1→F2→F3  Web 反馈上线         │ 约 8～12 周
   │  ★ 开始收用户反馈并周更              │
   │         │                           │
   │         └→ 反馈迭代（持续）           │
   │         └→ 移动 / 三端（加码，不挡反馈）
   │
   └────────【完整初版轨 · 反馈后】──────┐
      P0…P5  Web+Android+iOS 可用         │ 原 ~12 月，可压缩
      仍无盈利；功能仍是初版基本能力       │
```

**硬约束：** 尽快公网 Web 主闭环 + 反馈入口 → 再谈 App。盈利与功能全集不挡初版。

## 2. 快速轨摘要（执行这个）

详见 **[fast-launch.md](./fast-launch.md)**。

| 阶段 | 周期 | 终点 |
|------|------|------|
| F0 范围与云账号 | 1 周 | 范围冻结、域名/库/邮件/反馈渠道 |
| F1 公网后端 | 3～4 周 | Staging HTTPS、库、主闭环冒烟 |
| F2 Web 体验 | 3～4 周（重叠） | 引导/兑奖/见证/隐私/埋点/反馈入口 |
| F3 开放 | 1～2 周 | **★ 反馈上线** |
| F4+ | 滚动 | 按反馈改产品；可选开移动 |

### 反馈上线验收（§0.1 摘要）

HTTPS、注册登录、目标奖励闭环、待兑现、见证轻路径、契约基础、信任分、站内通知、**反馈入口**、隐私页、托管数据、关键计数 —— 全勾即宣布可收反馈。

## 4. 里程碑（以反馈为先）

| 里程碑 | 目标时间 | 验收 |
|--------|----------|------|
| **M-反馈** | Kickoff 后 **8～12 周** | [fast-launch §0.1](./fast-launch.md) 全勾；真实用户可访问并提交反馈 |
| **M-迭代** | 上线后持续 | 每周 progress 含反馈 Top 问题与改动 |
| **M-移动** | 有反馈样本后 | P3 起；不挡 Web |
| **M-商店** | 移动内测后 | 可选；非收反馈前提 |

### 使用指标（上线后观察，非营收）

| 指标 | 建议门槛 | 未达标 |
|------|----------|--------|
| 7 日创建带奖励目标 | ≥40% | 改引导/创建 |
| 达成者兑奖 | ≥30% | 加强待兑现 |
| 曾邀见证人 | ≥15% | 优化见证路径 |
| D7 留存 | ≥20%（可调） | 先改 Web，不急开功能面 |
| 达解锁门槛后申请解锁 | 观察 | 调门槛文案 / 进度可见性 |

市场对照与体验验收题见 [design.md](../design.md) §〇.1 · §十一。

## 5. 初版 Must / 不做

### 反馈上线 Must

见 [fast-launch.md §0.1](./fast-launch.md) 与 [初版.md](../versions/初版.md)。

### 明确不做（上线前）

- 任何盈利点  
- 终极版功能（押金、徽章墙、连坐、品牌券…）  
- 以 App 商店过审为「才能收反馈」的门槛  
- 手机号登录、完美 OpenAPI、完整渗透测试（底线安全即可）  

选型：Web Next.js + Express 演进；库 Postgres（或可备份托管）；移动 RN/Expo 待反馈后。
