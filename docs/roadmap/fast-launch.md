# 初版 · 快速上线计划（优先收反馈）

> **目标：** 在初版范围内，**尽快达到可上线标准**，让真实用户用起来并收集反馈。  
> **策略：** **Web 先上线收反馈**；Android / iOS 不挡反馈，按反馈后再加码。  
> **盈利：** 不做。  
> **起算：** 以 Kickoff 当周为 W0（文档示例按 2026-W30）。

口号：对自己守信，才能对他人守信。

---

## 0. 上线标准（什么叫「够快、够用」）

### 0.1 反馈上线（第一优先 · 约 8～12 周）

公网 **Web** 对真实用户开放（邀请制亦可），满足：

| # | 标准 | 说明 |
|---|------|------|
| 1 | HTTPS 公网可访问 | 固定域名；非仅 localhost |
| 2 | 注册登录可用 | 用户名+密码；资料可补邮箱 |
| 3 | 主闭环可走通 | 建目标（奖励必填）→ 进度 → 达成 → **兑奖** |
| 4 | 待兑现可发现 | 首页或列表有入口 |
| 5 | 见证人轻路径 | 可邀约 1 人（不强制） |
| 6 | 契约基础可用 | 可简化，不挡上线 |
| 7 | 信任分中性展示 | 有即可 |
| 8 | 站内通知基本可用 | 见证/兑奖相关优先 |
| 9 | 反馈入口 | 表单 / 邮箱 / 群之一；能收回意见 |
| 10 | 基础隐私页 | 隐私政策 + 用户协议可点开 |
| 11 | 数据不丢 | 托管库或等价；有备份意识（可简） |
| 12 | 关键埋点或日志 | 至少能数：注册、建目标、达成、兑奖 |

**达到 0.1 = 初版「可收反馈」上线。** 此后每周根据反馈改主路径，而不是先做 App。

### 0.2 初版完整（第二优先 · 反馈后滚动）

在 0.1 稳定跑、有反馈样本后：Android / iOS 内测→上架、推送、三端互通。  
**不以商店过审作为「开始收反馈」的前提。**

## 1. 为什么能快

| 砍掉 / 后置 | 理由 |
|-------------|------|
| 完整 Refresh / 设备会话打磨 | 先 JWT + HTTPS + 限流底线，安全加固与反馈并行 |
| 手机号登录 | 初版不做 |
| 原生 App / 商店 | 反馈后做 |
| OpenAPI 完美度 | 有核心说明即可；完美文档后置 |
| 压测与渗透全套 | 上线前做冒烟 + 基本安全自查 |
| 契约复杂编辑、AI 卖点 | 有基础即可；AI 可关 |
| 任何盈利 | 初版不做 |

试验版已有目标/兑奖/见证/契约雏形 → **重点是生产托管 + 公网 + 体验打磨 + 反馈通道**，不是重写产品。

## 3. 分阶段 Must（只做这些）

### F0 · 1 周

- [x] 确认执行 [初版.md](../versions/初版.md)，书面：**无盈利、Web 先反馈** → [decisions/2026-kickoff.md](./decisions/2026-kickoff.md)  
- [ ] 域名 + 云主机/PaaS + 托管库（**人工**；方案与 SQLite 卷备份见 [deployment.md](../deployment.md)）  
- [x] 邮件服务商申请（重置密码；试验期可双轨）→ **F3 前临时方案已落地**（`EXPOSE_RESET_URL` + `SUPPORT_EMAIL` / 反馈值班）  
- [x] 反馈渠道选定 → 站内 `/feedback` + `FEEDBACK_ADMIN_KEY` 值班拉取  

### F1 · 3～4 周

- [ ] API + Web 部署到公网 Staging，HTTPS（**人工挂域**；Compose + [Caddyfile](../../deploy/Caddyfile) 已备）  
- [x] 库迁移或直连托管库；seed 可在 staging 跑 → 卷持久化 + `npm run backup:db`  
- [x] 注册登录、忘记密码（真发信或明确「联系管理员」临时方案，**不超过 F3**）  
- [x] 健康检查；错误日志可查 → `/api/health` + Compose healthcheck  
- [x] 主闭环在 staging 冒烟通过 → 本地/`API_URL`：`npm run smoke`（公网待挂）

### F2 · 3～4 周（可与 F1 后半并行）

- [x] 注册后引导创建首个带奖励目标（修复竞态；onboarding 单屏目标+奖励+可选见证人）  
- [x] 待兑现入口；见证人邀 1 人路径可点通（姓名邀请 + 已注册用户；首页/目标列表兑奖 CTA）  
- [x] 空态文案去 Todo 感（对照 [design.md](../design.md)）  
- [x] 反馈入口进「我的」或页脚  
- [x] 隐私政策 / 用户协议页  
- [x] 埋点或等价日志：注册、建目标、达成、兑奖、反馈提交  

### F3 · 1～2 周 · ★ 反馈上线

- [ ] 邀请制或限流开放（防刷）  
- [ ] 对照 §0.1 清单全勾  
- [ ] 简单值班：谁看反馈、多久回一次  
- [ ] 宣布：**初版 Web 已上线，开始收使用反馈**  

### F4+ · 反馈后

- 每周：根据反馈改主路径（优先激活/兑奖/见证）  
- 指标见 [初版.md §2](../versions/初版.md)  
- 移动端：有稳定反馈样本后再开 [P3](./phases/P3-mobile-mvp.md)，不回头堵 Web

## 5. 反馈怎么收（上线即启用）

| 方式 | 最低配置 |
|------|----------|
| 产品内 | 「我的 / 页脚 → 意见反馈」链到表单或邮箱 |
| 邀请用户 | 首批 20～50 人（熟人 + 目标人群） |
| 节奏 | 每周五汇总进 [progress 周报](./progress/)：Top 问题 → 下 Sprint Must |
| 访谈 | 每两周 3～5 个用户短聊（主闭环是否看懂） |

## 6. 风险（快不等于乱）

| 风险 | 底线 |
|------|------|
| 数据丢失 | 托管库 + 至少周备份或平台自动备份 |
| 账号被刷 | 注册/登录限流；邀请码可选 |
| 无反馈 | 上线日即有入口 + 主动邀 20 人 |
| 范围回潮 | 任何「再加一个终极版功能」打回 [终极版](../versions/终极版.md) |
