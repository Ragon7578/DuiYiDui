# P1 · 后端生产化与账号体系

| 项 | 内容 |
|----|------|
| **周期** | 8～10 周（紧凑可压至约 6 周） |
| **累计月末** | 约 3 |
| **对应迭代** | Sprint 02～05（近期已排 02～04，其余按模板续排） |
| **关口** | Staging 全流程压测与安全自查；**SQLite 不再作生产主库** |
| **里程碑** | **M1 生产 API** |

---

## 阶段目标

任何一端只对接 **同一套生产级 API**：稳定数据层、正式账号、可观测、可灰度。

---

## 工作拆解

| 模块 | 工作项 | 周期（周） | 依赖 |
|------|--------|------------|------|
| **数据层** | SQLite → Postgres；迁移脚本；备份策略 | 2～3 | — |
| **账号安全** | Refresh Token；密码策略；登录限流；设备会话（可选） | 2 | 数据层启动后 |
| **邮件** | 重置密码真发信；可选注册验证；模板 | 1～2 | 邮件服务商 |
| **手机号**（若 V1 要） | 短信验证码绑定/登录 | 2 | 短信与资质 |
| **资料与注销** | 注销账号、导出数据 | 1 | 账号 |
| **业务 API 硬化** | 分页、幂等、错误码、OpenAPI | 2 | 可并行 |
| **通知服务** | 推送管道抽象（为 APNs/FCM 预留） | 1～2 | — |
| **观测** | 日志、错误追踪、基础指标、健康检查 | 1 | — |
| **环境** | Staging 独立库；密钥与 CI | 1～2 | — |

---

## 建议周序（稳健）

| 周序（相对 P1） | 焦点 |
|-----------------|------|
| W1～W2 | Postgres 迁移、备份、Staging 库 |
| W3～W4 | Refresh Token、限流、会话 |
| W5～W6 | 真邮件、资料/注销、OpenAPI 初稿 |
| W7～W8 | 通知抽象、观测、CI 密钥 |
| W9～W10 | 缓冲：手机号（若做）、压测、关口验收 |

---

## 验收清单

- [ ] Staging 多用户并发下「注册 → 绑邮箱 → 重置密码 → 目标全流程」通过  
- [ ] 生产配置不以本地 SQLite 文件为依赖  
- [ ] OpenAPI / 错误码文档可给移动端联调  
- [ ] 健康检查与基础错误追踪就绪  
- [ ] M1 评审通过  

---

## 与现状对照

| 现状（试验版） | 本阶段目标 |
|----------------|------------|
| Express + SQLite | Express（或等价）+ Postgres |
| JWT 试验登录 | Refresh + 限流 + 正式邮件 |
| 忘记密码可返回 resetUrl | 真发信为主路径 |
