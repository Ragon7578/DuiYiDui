# 功能规格（初版）

> **版本：** [初版](./versions/初版.md) — 尽快上线收反馈，**无盈利**。  
> **计划：** [roadmap/fast-launch.md](./roadmap/fast-launch.md)（约 8～12 周 Web）。  
> 全集与盈利见 [终极版](./versions/终极版.md)。  
> 视觉见 [design.md](./design.md)。

## 核心流程

```
设定目标 → 绑定奖励 → （建议）1 名见证人 → 追踪进度 → 达成 → 兑现奖励
                                                    ↘ 放弃 → 记入履约档案（影响信任分）
```

契约支线：创建 → 条款履约 → 完成 / 违约（初版保持可用，不与主路径抢首屏）。

## 0. 初版优先级

### 0.1 基本功能（Must）

| 优先级 | 能力 | 说明 |
|--------|------|------|
| P0 | 带奖励的目标全闭环 | 创建→进度→达成→**兑现**；奖励必填 |
| P0 | 「待兑现」可发现 | 首页 / 列表强提醒，防断环 |
| P0 | 见证人 ×1 轻路径 | 邀请 / 确认 / 通知；不强制 |
| P0 | 信任分中性展示 | 档案叙事；避免羞辱话术 |
| P1 | 契约基础 | 与他人约定；编辑可简化 |
| P1 | 通知 | 见证、截止、兑奖提醒优先 |
| P2 | 语音 / AI 创建 | 降摩擦；可降级；非主卖点 |
| — | 承诺 Pledge | 保留路由，**不进主导航** |

### 0.2 初版明确不做（含全部盈利）

- **任何实际盈利点**（会员、内购、广告变现、品牌券投放）  
- 虚拟押金、真金惩罚、公益资金池  
- 积分商城、完整徽章体系  
- 公开围观广场、连坐默认开启  
- 清单化：复杂标签、多优先级、无限子任务看板  
- 法律效力暗示  

以上归入 [终极版](./versions/终极版.md)。

### 0.3 使用指标（获客，非营收）

| 指标 | 建议门槛 | 对应功能 |
|------|----------|----------|
| 7 日内创建带奖励目标 | ≥40% 注册用户 | 注册引导 + 创建页 |
| 达成者中标记已兑现 | ≥30% | 兑奖入口与提醒 |
| 目标曾邀见证人 | ≥15% | 见证人轻路径 |
| D7 留存 | ≥20%（可按基线调） | 提醒 + 未兑现召回 |

未达门槛：优先改主路径与获客体验，**不开终极版功能，不上盈利**。

## 3. 目标管理

与**契约**的关系见下文「目标与契约」；目标是「对自己」的主线。

| 字段 | 必填 | 说明 |
|------|------|------|
| 标题 | 是 | 要做到什么 |
| 奖励 | 是 | 达成后给自己什么（**差异化核心**，现实奖励） |
| 描述 | 否 | 补充计划；勿压过奖励 |
| 截止日期 | 否 | 建议填写 |
| 见证人 | 否 | 建议 1 人；对方确认后，**你达成时见证人也会得成就点** |

**状态：** `active` → `achieved` → `reward_claimed`；或 `abandoned`。

**操作：** 更新进度、标记达成/放弃、兑现奖励、管理见证人（邀请 / 确认 / 拒绝）。

**场景：** 「连续跑步 30 天 → 新跑鞋」→ 进度 → 达成（本人信任分 +5）→ 若有已确认见证人（每人 +3）→ 兑现现实奖励。

**列表须暴露：** 奖励摘要、是否待兑现、见证状态（有/无）。

---

## 3.1 目标与契约（关系说明）

两者**并行、不父子绑定**，共同服务「说到做到」，并共用**信任分 / 成就点**：

```
                    ┌─ 目标：对自己 + 自我奖励（现实兑奖）
  说到做到 ─────────┤
                    └─ 契约：对他人 + 条款履约
                              │
                              ▼
                     信任分（成就点）同一套账户
```

| | 目标 | 契约 |
|--|------|------|
| 对象 | 自己 | 他人（参与方） |
| 现实回报 | **自我奖励**（产品核心字段） | 双方约定（可不填） |
| 成就点 | 本人达成 +5；放弃 -5 | 本人履行条款 +10；违约 -15 |
| 监督他人 | **见证人**：对方达成且你已确认见证 → 你 +3 | 你作为参与方履约即得分（上表） |
| 初版重心 | **主推**（获客闭环） | 基础可用，不抢首屏 |

一句话：**目标管「我答应奖励自己」；契约管「我们之间的约定」；自己做到或帮别人守住承诺，都能涨成就点。**

---

## 4. 契约管理

与他人约定；含参与方与条款。

| | 目标 | 契约 |
|--|------|------|
| 对象 | 自己 | 他人 |
| 奖励 | 自我奖励（现实） | 双方约定 |
| 监督 | 自己 / 见证人 | 参与方互相监督 |
| 成就点 | 见 §3.1 | 履行 +10 / 违约 -15 |

**契约状态：** draft / active / completed / breached / cancelled  
**条款状态：** pending / fulfilled / breached  

初版：保证基础履约与状态流转；复杂多人编辑、连坐归终极版。

---

## 5. 承诺（Pledge）

轻量一句话承诺；有 API 与 `/pledges` 页，**主导航未挂载**（可从 URL 进入）。  
适合尚未形成完整「目标+奖励」时的记录；**不作为获客主故事**，以免稀释「兑现」心智。

## 6. 创建页

- Tab：目标 | 契约；默认目标  
- 目标模式：**奖励必填**，字段靠前  
- 见证人：可选 + 「建议邀请 1 人」提示  
- **语音输入**（浏览器 Speech API，视环境而定）  
- **智能填写**：调用 `POST /api/ai/parse` 解析自然语言

## 7. 通知

- 列表、未读数、单条/全部已读  
- **优先类型：** 见证邀请/响应、截止提醒、达成祝贺、**兑奖提醒**  
- 导航显示未读角标  
- 违约类通知保持克制（与 design「信用非羞辱」一致）

## 8. 信任体系（成就点）

| 事件 | 分值 | 角色 |
|------|------|------|
| 目标达成 | +5 | **自己**做到 |
| 目标放弃 | -5 | 自己 |
| 契约履行 | +10 | **自己**作为参与方履约 |
| 契约违约 | -15 | 自己 |
| 见证的目标达成 | +3 | **监督他人**：已确认的见证人 |
| 默认 / 范围 | 50 起；约 0–100 | 同一套信任分 |

展示：首页、我的（达成率/放弃率条）。  
**产品说明：** 自己达成涨分，认真监督别人达成也涨分；看长期趋势，不是羞辱工具。

## 11. UX 要点

- 奖励必填：逼用户想清回报  
- 达成后提醒兑现，形成闭环；待兑现可发现  
- 见证人轻量可触达，服务留存与拉新  
- 放弃记「放弃/未完成」，避免过度羞辱话术  
- 任何新功能上线前自问：是否让产品更像 Todo？若是则降级或拒绝
