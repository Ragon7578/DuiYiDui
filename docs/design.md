# UI/UX 设计

## 一、设计理念

### 核心理念：信任、简洁、可靠

| 原则 | 说明 |
|------|------|
| **信任感** | 视觉风格稳重、干净，使用黑白色为主调，传递可靠感 |
| **简洁** | 减少不必要的装饰，内容优先，信息层级清晰 |
| **反馈即时** | 状态变化通过标签和颜色即时反映，用户始终知道"当前处于什么状态" |

### 色彩系统

| 用途 | 颜色 | Tailwind |
|------|------|----------|
| 主色 | 黑色 | `black` / `text-black` / `bg-black` |
| 文字次要 | 灰色 | `text-gray-500` |
| 文字辅助 | 浅灰 | `text-gray-400` |
| 背景 | 浅灰 | `bg-gray-50` |
| 卡片背景 | 白色 | `bg-white` |
| 边框 | 浅灰 | `border-gray-200` |
| 成功/履行 | 绿色 | `text-green-700` / `bg-green-100` |
| 违约/失败 | 红色 | `text-red-700` / `bg-red-100` |
| 进行中 | 蓝色 | `text-blue-700` / `bg-blue-100` |
| 草稿/待定 | 灰色 | `text-gray-700` / `bg-gray-100` |
| 已取消 | 黄色 | `text-yellow-700` / `bg-yellow-100` |

### 排版

- 字体：Geist (Vercel 出品，现代无衬线体)
- 层次：
  - 页面标题：`text-2xl font-bold`
  - 卡片标题：`text-lg font-semibold`
  - 正文：`text-sm` / `text-base`
  - 辅助信息：`text-xs text-gray-400`

## 三、交互规范

### 3.1 状态标签

所有状态使用圆角标签展示，带语义颜色：

| 状态 | 颜色 | 预览效果 |
|------|------|----------|
| 草稿 | 灰色 | `[ 草稿 ]` |
| 进行中 | 蓝色 | `[ 进行中 ]` |
| 已完成 | 绿色 | `[ 已完成 ]` |
| 违约 | 红色 | `[ 违约 ]` |
| 已取消 | 黄色 | `[ 已取消 ]` |
| 已履行 | 绿色 | `[ 已履行 ]` |
| 待处理 | 灰色 | `[ 待处理 ]` |
| 未履行 | 红色 | `[ 未履行 ]` |
| 活跃 | 蓝色 | `[ 活跃 ]` |

### 3.2 卡片交互

- **默认**：白色背景，浅灰边框，无阴影
- **Hover**：轻微上浮阴影 (`hover:shadow-md`)
- **点击**：整张卡片可点击，进入详情页

### 3.3 导航

- 固定顶部，始终可见
- 当前页导航项黑色加粗，其余灰色
- 品牌名"契约精神"在左侧，点击回到首页

### 3.4 空状态

- 列表无数据时显示灰色提示文字
- 例如："暂无进行中的契约"、"暂无活跃承诺"

## 四、响应式设计

| 断点 | 宽度 | 布局变化 |
|------|------|----------|
| 默认 | < 1024px | 单列，统计卡片 2×2 网格 |
| `lg` | ≥ 1024px | 统计卡片 4 列，详情页 2 列 |

### 移动端适配（当前）

- 最大宽度 `max-w-5xl`，居中
- 导航可正常展示，后续移动端可改为汉堡菜单
