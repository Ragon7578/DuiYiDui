# UI/UX 设计规范

> 以 `apps/web` 当前实现为准（墨色印章风），旧「黑白 + Geist」描述已废弃。  
> **版本：** 默认描述 **[初版](./versions/初版.md)** — 基本功能、吸引用户使用、**无盈利 UI**。  
> 全集与盈利视觉见 [终极版](./versions/终极版.md)。设计优先：可理解性、闭环完成率、次周留存。

---

## 〇、产品体验定位（设计必守）

一句话：**帮用户把「做到了就奖励自己」写清楚、追下去、兑得了；信用可见，可被一人见证。**

| 我们是 | 我们不是 |
|--------|----------|
| 承诺—奖励—兑现的闭环工具 | 又一个 Todo / 打卡清单 |
| 轻量自我约定 + 可选见证 | 法律电子签、催收、公开处刑 |
| 信任分 = 履约档案趋势 | 羞辱排行榜 |

**初版主路径（获客）：**

1. 创建一个**带具体奖励**的目标  
2. （强烈建议）邀请 **1 名**见证人（情侣 / 好友）并请对方确认  
3. 更新进度 → 达成（**本人成就点 +5**；已确认见证人各 **+3**）→ **现实兑现后**勾「奖励已兑现」  
4. 在首页看到信用与「说到做到」的反馈  

**目标 vs 契约（须说清）：** 目标 = 对自己 + 自我奖励；契约 = 对他人约定。两条线并行，成就点进同一信任分。监督他人（确认见证后对方达成）同样得分。

复杂多人契约、游戏化押金、徽章商城、品牌券、会员墙等**不得挤占**初版首屏与创建心智（均属终极版）。

## 一、设计理念

| 原则 | 说明 | 市场含义 |
|------|------|----------|
| 信任感 | 稳重纸感 + 清晰层级，少喧闹装饰 | 承诺工具要「郑重」，不像娱乐 App |
| 品牌优先 | 「兑一兑」为展示主角；英文副标 DuiYiDui | 首屏去掉品牌后仍应认得是本产品 |
| 奖励突出 | 创建与详情里，奖励是心理设计核心，不是备注 | 差异化；防滑向待办 |
| 兑现仪式 | 达成后必须有明确「去兑现」引导与完成态 | 验证「兑得了」是否被使用 |
| 见证轻量 | 默认邀 1 人；流程短、话术鼓励而非强迫 | 提高社交约束与自然拉新 |
| 状态可见 | Badge / 色块表达进行中、达成、已兑现、放弃 | 降低「说过就忘」 |
| 信用非羞辱 | 信任分强调趋势与档案；违约默认克制、可选通知范围 | 降低卸载与回避 |
| 一件事一屏 | 首屏 / 空态只推一条主行动 | 降认知负荷，提激活率 |

## 二、文案与反模式

### 推荐话术方向

| 场景 | 推荐 | 避免 |
|------|------|------|
| 空态（无目标） | 「写下一件要对得起自己的事，并想好奖励」 | 「创建你的第一条待办」 |
| 奖励字段 | 「做到了，你打算奖励自己什么？」 | 「备注 / 标签」 |
| 达成后 | 「奖励还在等你——兑现后记得勾掉」 | 仅「已完成 ✓」无兑奖引导 |
| 放弃 | 「记录下来，下次可以换一种承诺」 | 「你失败了 / 失信」刺激性羞辱 |
| 见证人 | 「找一个在乎你说到做到的人」 | 「公开围观 / 打卡广场」 |
| 信任分 | 「你的履约档案」；波动用中性说明 | 大红「扣分警告」恐吓 |

### 体验反模式（设计评审直接打回）

- 把目标列表做成清单 App：多字段优先级、标签墙、无限子任务堆叠  
- 首屏堆统计卡片、排行、运营 Banner，挤掉「进行中的承诺」  
- 创建流程奖励可选或藏在折叠区  
- 未达成就默认广播给所有好友 / 公开动态  
- 为游戏化（积分商城、押金）改导航结构，削弱目标 / 兑现

## 三、设计 Token（`globals.css`）

| Token | 色值（约） | 用途 |
|-------|------------|------|
| `--ink` | `#0c0f14` | 主文字、主按钮底 |
| `--paper` / `--paper-deep` | `#f3f5f8` / `#e6eaef` | 背景、浅底 |
| `--seal` / `--seal-soft` | `#c81e1e` / `#fde8e8` | 强调、必填、危险弱提示 |
| `--line` | `#c8d0db` | 边框分割 |
| `--muted` | `#5c6678` | 次要文字 |
| `--ok` / `--ok-soft` | 绿系 | 成功、履行、**已兑现** |
| `--warn` / `--info` | 黄 / 蓝系 | 警告、信息 |

背景：浅色纸感 + 微弱径向渐变与噪点，非纯扁平单色。

**语义约定：** 「奖励已兑现」用成功色强化闭环；「放弃」用中性或弱 warn，避免 seal 大红铺满造成羞辱感。

## 四、字体

| 角色 | 字体 | CSS |
|------|------|-----|
| 展示 / 品牌 / 大标题 | Noto Serif SC | `.font-display` |
| 正文 / UI | Outfit | `body` / `--font-body` |

**不要**再使用 Geist 作为规范字体。

## 五、组件约定

| 组件 | 约定 |
|------|------|
| `FormLabel` | 必填项显示印章色 `*`；**奖励字段标签用完整问句或加粗提示** |
| `Badge` | 语义色映射状态；增加/保留「已兑现」态，与「已达成」区分 |
| `Card` | 内容分区；非交互列表避免过度「卡片堆」 |
| 主按钮 | `.btn-primary`（墨底）；达成页主 CTA = 兑现奖励 |
| 输入 | `.input-field` |

## 六、导航

登录后主导航（按角色）：

首页 · **我的** · **监督** · 创建  

| 导航 | 过渡路由 | 角色 |
|------|----------|------|
| 我的 | `/goals` | 对自己：承诺与兑奖 |
| 监督 | `/contracts` | 监督他人：约定 / 见证（多用户） |

右侧 **头像菜单** 收纳：我的信息、通知、意见反馈、登出。  
未登录：主导航仅首页；头像菜单内为登录 / 注册。

- 品牌「兑一兑」点回首页（欢迎页）  
- 通知未读数显示在头像角标与菜单项上  
- `/pledges` 有路由，**默认不进主导航**  
- 角色与双套演进见 [product-roles.md](./product-roles.md)

## 七、关键页面要点

### 认证

- 注册：仅用户名 + 密码 + 确认密码（降低激活摩擦）  
- 登录：用户名 + 密码；链到忘记密码  
- 忘记密码：邮箱；试验环境可展示重置链接  
- 重置密码：token 查询参数  
- 注册成功后：**优先引导创建第一个带奖励的目标**，而非空仪表盘  

### 首页（欢迎页）

对所有人开放，不强制登录。

- **未登录：** 品牌欢迎 + 一句话价值 + 开始使用 / 登录；下方三点说明  
- **已登录：** 欢迎区 + 待兑现 / 进行中目标与契约摘要  

账号相关一律进头像菜单，不占顶栏。

### 目标

- 列表强调奖励摘要与状态（含「待兑现」）  
- 达成后强引导兑现；未兑现应在列表/首页可发现  
- 见证人：创建或详情内 **一键邀 1 人**；文案鼓励，不强制  
- 避免做成看板 / 多视图待办  

### 创建

- Tab：目标 | 契约；**默认落在目标**  
- 目标模式：**奖励必填**，字段位置靠前（标题之后即奖励优于长描述）  
- 见证人：可选，默认折叠但可见「建议邀请 1 人」  
- 语音 / AI：辅助降低填写成本；失败须无感回退手动；不作为主卖点压过奖励  

### 契约

- 初版保持基础可用；创建复杂度低于目标主路径  
- 连坐、公开围观等不进初版默认 UI 

### 我的

- 可编辑邮箱、手机、简介；只读登录名  
- 履约率与目标记录；信任分说明链到「档案」叙事  
- 不放积分商城、押金、会员墙（终极版） 

### 通知

- 优先：见证邀请、截止临近、达成祝贺、**提醒兑奖**  
- 违约通知：默认克制；尊重隐私设置（规划项落地前勿默认广播）

## 八、空态 / 错态 / 加载

| 状态 | 要求 |
|------|------|
| 空目标列表 | 单主 CTA + 一句「奖励要写清」；可给 1 个示例（如跑步→跑鞋） |
| 已达成未兑现 | 单独空态或横幅，主 CTA「标记奖励已兑现」 |
| 无见证人 | 详情内轻提示，非全屏打断 |
| 错态 | 可行动的下一句；忌技术堆栈暴露 |
| 加载 | 骨架或短文案，避免误以为无数据 |

---

## 九、动效

- 入场：`animate-rise` 等轻微上浮  
- 导航激活：印章色下划线  
- **兑现成功**：允许一次短促确认反馈（勾选/印章感），强化仪式  
- 避免过量 glow / 紫渐变（与产品视觉方向不符）  

---

## 十、响应式

- 内容最大宽约 `max-w-5xl` 居中  
- 小屏保证主 CTA 可达；导航可横向压缩；后续可考虑底栏  
- 公测阶段移动浏览器可用优先于原生 App 视觉对齐  

---

## 十一、体验成功标准（设计验收）

与路线图公测门槛对齐；设计改版应用这些题自测：

| 问题 | 合格标准 |
|------|----------|
| 新用户 30 秒内能否说出产品干什么？ | 能答出「目标+奖励+兑现」或等价 |
| 创建页是否可能漏填奖励？ | 不能（校验 + 视觉权重） |
| 达成后是否可能忘记兑奖？ | 首页/列表有待兑现入口 |
| 是否像 Todo？ | 评审 3 人中 ≥2 人否定 |
| 信任分是否引起不适？ | 文案走档案/趋势，无恐吓默认 |

量化门槛见 [roadmap/README.md](./roadmap/README.md) 市场验证节与 [features.md](./features.md)。
