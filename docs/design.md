# UI/UX 设计规范

> 以 `apps/web` 当前实现为准（墨色印章风），旧「黑白 + Geist」描述已废弃。  
> **版本：** 默认描述 **[初版](./versions/初版.md)** — 基本功能、吸引用户使用、**无盈利 UI**。  
> 全集与盈利视觉见 [终极版](./versions/终极版.md)。  
> **角色 IA：** [product-roles.md](./product-roles.md)（我的 / 他人 · 解锁门 · 成长条规划）。  
> 设计优先：可理解性、闭环完成率、次周留存。

**文档版本：** 2026-07-31 · 含市场对照与双角色门禁体验。

## 〇、产品体验定位（设计必守）

一句话：**帮用户把「做到了就奖励自己」写清楚、追下去、兑得了；信用可见，可被一人见证；先对自己守信，再解锁帮他人盯约定。**

| 我们是 | 我们不是 |
|--------|----------|
| 承诺—奖励—兑现的闭环工具 | 又一个 Todo / 打卡 / 连击清单 |
| 正向自我奖励 + 轻量见证 | 真金押注、反慈善惩罚（stickK / Beeminder 路径） |
| 轻量自我约定 + 可选见证 | 法律电子签、催收、公开处刑 |
| 信任分 = 履约档案趋势 | 羞辱排行榜、连坐默认开 |
| 双角色：我的 →（解锁）他人 | 一上来就逼社交 / 监督他人 |

**初版主路径（获客）：**

1. 创建一条**带具体奖励**的「给自己的项目」  
2. （强烈建议）邀请 **1 名**见证人并请对方确认  
3. 更新进度 → 达成 → **现实兑现后**勾「奖励已兑现」  
4. 累计达成达到门槛后，**申请解锁**「他人」角色，再建给别人的项目  
5. 首页看到信用与「说到做到」的反馈  

复杂多人契约、游戏化押金、徽章商城、品牌券、会员墙、AI 卖点墙等**不得挤占**初版首屏与创建心智（均属终极版或后置）。

## 〇.1 市场对照（设计决策依据）

> 习惯 / 问责类 App 赛道增长快（公开估算 CAGR 约 14%），但**同质化严重、30 日流失普遍偏高**。兑一兑不跟「打卡连击 + 清单」正面撞车，而在**承诺装置（commitment device）**里走**正向兑现**切口。

### 竞品地图（设计该学什么 / 不学什么）

| 代表 | 核心机制 | 对我们有用的启发 | 明确不做 / 延后 |
|------|----------|------------------|-----------------|
| **stickK** | 承诺合同 + 可选金钱 / 反慈善惩罚 + 裁判 | 「写下来 + 有人看着」有效；裁判≈见证人 | 真金惩罚、反慈善羞辱感 |
| **Beeminder** | 数据曲线 + 自动扣款 + 多源同步 | 进度要可见、断档要有后果感 | 金钱损失主叙事、复杂数据集成（初版） |
| **Habitica** | RPG / 组队失败连坐 | 社交约束能提留存 | 游戏化主导航、连坐默认开 |
| **HabitShare 等** | 朋友间晒习惯 | 熟人问责优于广场 | 公开动态墙、打卡广场 |
| **Fabulous / Finch** | 行为科学课程 / 情感陪伴 | 话术要温和、引导要短 | 厚重课程墙、宠物养成抢「兑现」心智 |
| **TickTick / 待办系** | 任务 + 习惯子模块 | 注册要低摩擦 | **Todo 化列表、标签墙、多优先级** |

### 兑一兑差异化（设计必须看得见）

| 维度 | 市场常见 | 兑一兑初版 |
|------|----------|------------|
| 动机方向 | 损失厌恶（扣钱 / 断连击） | **收益兑现**（想好奖励 → 做到了真去拿） |
| 闭环终点 | 「打卡完成」 | **「奖励已兑现」** 才是闭环 |
| 社交 | 广场 / 组队 / 金钱裁判 | **1 名熟人见证**；他人角色**需先达成自身计划再解锁** |
| 信用 | 排行或无 | **履约档案**（中性，非羞辱） |
| 商业 | 订阅墙常挡主路径 | **初版无盈利 UI** |

### 行业痛点 → 设计对策

| 市场痛点 | 设计对策 |
|----------|----------|
| 30 日内大量卸载 | 首屏一件事；注册后立刻写「带奖励」承诺；**待兑现召回**优先于新功能 |
| 「又一个习惯 App」认知 | 文案与字段强制出现「奖励 / 兑现」；评审「是否像 Todo」一票否决 |
| 社交问责摩擦高 | 见证可选；他人角色渐进解锁（先自证履约） |
| AI 功能同质化 | 语音 / 解析仅辅助填表；失败静默回退；不占首屏卖点 |
| 惩罚型产品劝退温和用户 | 放弃话术中性；信任分不用大红恐吓；违约通知默认克制 |

**目标人群（设计写给谁看）：** 想对自己守信、愿用「奖励」而非「惩罚」驱动的人；情侣 / 好友轻监督；**不**优先讨好清单控、硬核数据极客、押金爱好者。

## 一、设计理念

| 原则 | 说明 | 市场含义 |
|------|------|----------|
| 信任感 | 稳重纸感 + 清晰层级，少喧闹装饰 | 承诺工具要「郑重」，不像娱乐 / 养成游戏 |
| 品牌优先 | 「兑一兑」为展示主角；英文副标 DuiYiDui | 首屏去掉品牌后仍应认得是本产品 |
| 奖励突出 | 创建与详情里，奖励是心理设计核心，不是备注 | 对位 stickK「合同」、我们「兑奖」；防滑向待办 |
| 兑现仪式 | 达成后必须有明确「去兑现」引导与完成态 | 验证差异化是否被使用（指标：达成者兑奖率） |
| 见证轻量 | 默认邀 1 人；流程短、话术鼓励而非强迫 | 熟人问责；避开广场与连坐劝退 |
| 先我后人 | 他人角色默认锁定；达成门槛后申请解锁 | 降低「空账号乱监督」；强化品牌句「对自己守信…」 |
| 状态可见 | Badge 表达进行中、达成、已兑现、放弃、待解锁 | 降低「说过就忘」；进度感不必靠金钱曲线 |
| 信用非羞辱 | 信任分强调趋势与档案 | 对冲惩罚型竞品的劝退 |
| 一件事一屏 | 首屏 / 空态只推一条主行动 | 对抗行业高流失 |

## 二、文案与反模式

### 推荐话术方向

| 场景 | 推荐 | 避免 |
|------|------|------|
| 空态（无项目） | 「写下一件要对得起自己的事，并想好奖励」 | 「创建你的第一条待办 / 习惯」 |
| 奖励字段 | 「做到了，你打算奖励自己什么？」 | 「备注 / 标签」 |
| 达成后 | 「奖励还在等你——兑现后记得勾掉」 | 仅「已完成 ✓」无兑奖引导 |
| 放弃 | 「记录下来，下次可以换一种承诺」 | 「你失败了 / 失信」刺激性羞辱 |
| 见证人 | 「找一个在乎你说到做到的人」 | 「公开围观 / 打卡广场」 |
| 信任分 | 「你的履约档案」；波动用中性说明 | 大红「扣分警告」恐吓 |
| 他人未解锁 | 「先完成若干给自己的项目，再申请解锁他人」 | 「立即监督好友」「开通 VIP 解锁」 |
| 价值主张 | 「做到了，兑一兑」 | 「打卡 Native / 连击不断」 |

### 体验反模式（设计评审直接打回）

- 把列表做成清单 App：多字段优先级、标签墙、无限子任务堆叠  
- 首屏堆统计卡片、排行、运营 Banner，挤掉「进行中的承诺 / 待兑现」  
- 创建流程奖励可选或藏在折叠区  
- 未达成就默认广播给所有好友 / 公开动态  
- 为游戏化（积分商城、押金）改导航结构，削弱目标 / 兑现  
- 用金钱惩罚或反慈善作为默认激励（属终极版审慎议题，初版禁止）  
- 未解锁他人时仍强推「创建监督约定」为主 CTA

## 三、设计 Token（`globals.css`）

| Token | 色值（约） | 用途 |
|-------|------------|------|
| `--ink` | `#0c0f14` | 主文字、主按钮底 |
| `--paper` / `--paper-deep` | `#f3f5f8` / `#e6eaef` | 背景、浅底 |
| `--seal` / `--seal-soft` | `#c81e1e` / `#fde8e8` | 强调、必填、危险弱提示 |
| `--line` | `#c8d0db` | 边框分割 |
| `--muted` | `#5c6678` | 次要文字 |
| `--ok` / `--ok-soft` | 绿系 | 成功、履行、**已兑现** |
| `--warn` / `--info` | 黄 / 蓝系 | 警告、信息 |

背景：浅色纸感 + 微弱径向渐变与噪点，非纯扁平单色。

**语义约定：** 「奖励已兑现」用成功色强化闭环；「放弃」与「未解锁」用中性或弱 warn，避免 seal 大红铺满造成羞辱感。锁态可用小号「锁」字标，**不用恐吓图标墙**。

## 五、组件约定

| 组件 | 约定 |
|------|------|
| `FormLabel` | 必填项显示印章色 `*`；**奖励字段标签用完整问句或加粗提示** |
| `Badge` | 语义色映射状态；「已兑现」与「已达成」必须区分 |
| `Card` | 内容分区；非交互列表避免过度「卡片堆」 |
| 主按钮 | `.btn-primary`（墨底）；达成后主 CTA = 兑现奖励 |
| 输入 | `.input-field` |
| 解锁门禁 | 进度条（已达成 / 门槛）+ 单一主 CTA（去创建自身项目 / 申请解锁）；见 [product-roles §2.1](./product-roles.md) |

## 六、导航与角色

登录后主导航：

**首页 · 我的 · 他人 · 创建**

| 导航 | 过渡路由 | 角色 / 项目语义 | 门禁 |
|------|----------|-----------------|------|
| 我的 | `/goals` | 给自己的项目：承诺与兑奖 | 无 |
| 他人 | `/contracts` | 给别人的项目：约定 / 见证 | 默认锁定；解锁后可创建 |
| 创建 | `/create` | 无 `?set=` 先选角 | 他人卡片在未解锁时禁用 |

右侧 **头像菜单**：我的信息、通知、意见反馈、登出。  
未登录：主导航仅首页。

- 品牌「兑一兑」点回首页  
- 通知未读在头像角标  
- `/pledges` **不进主导航**  
- 成长条（规划）：各角色独立进度壳层，**不替代**信任分；详见 [product-roles §5](./product-roles.md)

### 解锁门禁 UX（他人）

| 状态 | 界面 |
|------|------|
| 未达门槛 | 「他人」可进，展示进度与「去创建给自己的项目」；创建选角里他人卡片灰显 |
| 可申请 | 同一门禁卡片主 CTA 变为「申请解锁他人角色」 |
| 已解锁 | 正常列表 + 创建入口；导航锁标消失 |
| 仅被邀请 | 可查看自己参与的他人项目，但**创建**仍受解锁限制 |

门槛默认 **达成 3 个**给自己的项目（可配置）；文案强调「申请」而非「购买」。

## 七、关键页面要点

### 认证

- 注册：仅用户名 + 密码（降低激活摩擦）  
- 登录后可补邮箱 / 手机  
- 注册成功：**引导创建第一条带奖励的给自己的项目**（可 `?onboarding=1`，仍先选角但文案偏向「我的」）  

### 首页（欢迎页）

- **未登录：** 品牌 + 价值句 + 开始使用；下方三点：**写清奖励 / 可以有人看着 / 信用看得见**  
- **已登录：** 待兑现优先于一切统计；再分「我的 · 进行中」「他人 · 进行中」  
- 未解锁时，他人相关 CTA 用「他人角色待解锁」，链到解锁说明，**不要**假装可直接创建  

### 我的（给自己的项目）

- 列表强调奖励摘要与「待兑现」  
- 见证人：一键邀 1 人；不强制  
- 避免看板 / 多视图待办  

### 创建

- 无 `set`：**选角两卡**（给自己的项目 / 给别人的项目）  
- 我的表单：**奖励必填且靠前**；见证人可选  
- 他人表单：须真实用户 + 条款；未解锁时不进表单，进解锁门  
- 语音 / AI：辅助填表；失败回退手动；**不作为主卖点**  

### 他人（给别人的项目）

- 初版基础可用；复杂度低于「我的」主路径  
- 连坐、公开围观不进默认 UI  
- 空态与锁态文案走「先自证再帮人」  

### 我的信息

- 履约率与信任分走「档案」叙事  
- 可展示解锁进度（可选）；不放会员墙  

### 通知

- 优先：见证、截止、达成祝贺、**兑奖提醒**  
- 可申请解锁时：一条中性通知（可选，勿刷屏）  
- 违约通知：默认克制

## 八、空态 / 错态 / 加载

| 状态 | 要求 |
|------|------|
| 空「我的」列表 | 单主 CTA + 「奖励要写清」；可给 1 个示例（跑步→跑鞋） |
| 已达成未兑现 | 横幅或区块，主 CTA「标记奖励已兑现」 |
| 他人未解锁 | 解锁门禁卡，勿空白误以为故障 |
| 无见证人 | 详情内轻提示，非全屏打断 |
| 错态 | 可行动的下一句；忌技术堆栈 |
| 加载 | 骨架或短文案，避免误以为无数据 |

## 九、动效

- 入场：`animate-rise` 等轻微上浮  
- 导航激活：印章色下划线  
- **兑现成功**：短促确认（勾选 / 印章感），强化仪式  
- **解锁成功**：允许一次轻反馈，勿烟花式庆祝压过「兑奖」心智  
- 避免过量 glow / 紫渐变

## 十、响应式

- 内容最大宽约 `max-w-5xl` 居中  
- 小屏主 CTA 可达；公测优先移动浏览器可用，再谈原生视觉对齐

## 十一、体验成功标准（设计验收）

| 问题 | 合格标准 |
|------|----------|
| 新用户 30 秒内能否说出产品干什么？ | 能答「目标+奖励+兑现」或等价，而非「打卡 / 待办」 |
| 创建页是否可能漏填奖励？ | 不能（校验 + 视觉权重） |
| 达成后是否可能忘记兑奖？ | 首页 / 列表有待兑现入口 |
| 是否像 Todo / Habit Tracker？ | 评审 ≥2/3 否定 |
| 信任分是否引起不适？ | 档案 / 趋势话术，无恐吓默认 |
| 未解锁用户是否被强推他人创建？ | 否；锁态与进度说明清晰 |
| 与 stickK/Beeminder 是否被误认为「扣钱 App」？ | 否；无金钱惩罚主路径 |

量化门槛见 [roadmap/README.md](./roadmap/README.md) 与 [features.md](./features.md)（创建率、兑奖率、见证率、D7）。
