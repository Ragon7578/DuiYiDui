# 上篇 · 现行介绍与可演示能力

## 1. 开场：我们相信什么

很多人并不缺少目标，缺少的是：**对自己说过的话负责。**

「瘦下来就买包」「项目上线就去旅行」「今年读完二十本书」——话出口时很轻，兑现时却没人记得，最后连自己都不好意思再提。

**兑一兑**相信：

- 对自己守信，是对他人守信的起点  
- 奖励不是奢侈，而是履约的燃料  
- 记录不是束缚，而是尊重自己的一种方式  
- 承诺写下来就该有重量；信用可以积累，也可以受损  

所以产品英文名是 **DuiYiDui——做到了，兑一兑。**

---

## 2. 要解决的问题

常见落空不是因为「做不到」，而是因为过程里缺了这些东西：

| 缺口 | 现实里发生的事 |
|------|----------------|
| 没有成本 | 承诺太随意，不当回事 |
| 没有记录 | 说过就忘 |
| 没有追踪 | 达成那天，奖励早忘了 |
| 没有监督 | 没人问一句「你上次说的呢？」 |
| 没有反馈 | 履约/违约都像没发生过 |

我们要提供的，不是又一个待办清单，而是一个让承诺**可记录、可追踪、可兑现、可回顾**，并让**信用可见**的地方。

## 3. 产品定位（两版表述均保留）

### 表述 A（现行试验版口径）

**兑一兑**是一款以 **目标达成 + 自我奖励** 为核心的承诺管理工具，并支持与他人订立轻量约定。

它填补中间地带：

```
口头承诺          兑一兑           正式合同
（太轻、易忘）  ←——————→    （太重、门槛高）
```

| 结果 | 含义 |
|------|------|
| **做到了** | 奖励是你的，系统提醒你去兑现 |
| **没做到** | 不是羞辱，但有据可查——赖不掉 |

**当前形态：** 浏览器 Web 试验版。  
**规划形态：** 同一账号下 Web、Android、iOS 三端互通。  
**市场切入：** 开发执行 **[初版](./versions/初版.md)** — 基本功能、吸引用户使用、**不要求盈利**；规划全集与盈利见 **[终极版](./versions/终极版.md)**。对外避免「又一个待办 / 习惯 App」表述。  
在问责 / 习惯赛道中，兑一兑走**正向兑现**（想好奖励 → 做到了真去拿），不对齐 stickK / Beeminder 式金钱惩罚主路径；他人监督需先完成自身计划再解锁。体验细则见 [design.md](./design.md) §市场对照。  
**开发计划：** 按 [./versions/初版.md](./versions/初版.md) 执行 **[快速上线](./roadmap/fast-launch.md)**（约 8～12 周 Web 公网收反馈；App 后置）。

### 表述 B（产品规划口径，完整保留）

**兑一兑**是一款以 **「自我承诺 + 社交见证 + 信用积累」** 为核心的目标管理应用。

它不是又一个 Todo List，而是一套**个人信用系统**——你给自己定目标、立契约、找见证人，履约则信用增长，违约则信用受损。用「面子」和「信用」驱动执行力。

## 4. 核心理念（合并）

### 四句话【当前强调】

1. **对自己诚实** — 承诺写清楚，不留模糊空间  
2. **用奖励驱动** — 先想清「做到了能得到什么」  
3. **违约有痕迹** — 记录提醒，而非道德审判  
4. **信任看得见** — 履约档案沉淀为信任分  

### 理念表【规划稿完整保留】

| 理念 | 说明 |
|------|------|
| 承诺即契约 | 写下来的目标不是「待办」，是和自己签的「合同」 |
| 信用可量化 | 信任分 ≈ 履约表现，可积累、可展示 |
| 社交即约束 | 见证人看着你，违约可被通知；外部目光增强执行力 |
| 奖惩对等 | 达成有奖励（自定义 + **规划：品牌券**）；违约有代价（扣分 + **规划：押金扣除**） |
| 轻量优先 | 可 30 秒创建一条承诺，不强制走完整契约流程 |

### 成长路径

```
对自己守信  →  对他人守信  →  建立可感知的社会信任
   （目标）        （契约 / 见证）
```

### 正循环

| 要素 | 作用 |
|------|------|
| 目标 | 明确要做什么 |
| 奖励 | 给兑现一个具体理由 |
| 记录 | 让承诺不易「假装没说过」 |
| 追踪 | 随时看见进度 |
| 兑现 | 完成闭环，强化下次承诺 |
| 信用 | 让长期守信被看见 |

### 产品原则

| 原则 | 含义 |
|------|------|
| 轻量 | 不搞复杂法律条款与正式签署仪式 |
| 真实 | 不为打卡而打卡，强调说到做到 |
| 不装 | 界面与话术直接，少套路 |
| 奖励优先 | 创建目标时，奖励是核心字段 |

视觉气质（当前 Web）：纸感背景、墨色文字、印章红强调——偏「立字为据」。  
规划中亦包含游戏化、徽章、积分等反馈（见下篇）；两套气质可并存于不同阶段。

## 5. 两条主线流程【当前】

顶层按**两个角色**组织（导航：**我的** / **监督**），不是「目标下面挂契约」。  
两条线都服务「说到做到」，共用信任分；监督侧默认**多用户**（真实账号互盯）。  
工程过渡期路由仍为 `/goals`、`/contracts`，详见 [product-roles.md](./product-roles.md)。

```
说到做到
├── 我的（Self）—— 对自己：写清要做的事 + 自我奖励 → 做到 → 兑现
│                 （可选请人见证；对方在「监督」侧确认）
└── 监督（Supervise）—— 盯他人：约定参与方 / 见证 → 履约或违约有痕迹
```

### 主线 A：我的（对自己 · 最常用）

```
设定承诺 → 绑定奖励 → （建议）邀请见证人并确认
       → 追踪进度 → 达成（本人成就点 +5；见证人各 +3）→ 兑现奖励
                  ↘ 放弃 → 记入档案（本人 -5）
```

### 主线 B：监督（对他人 · 多用户）

```
创建监督约定 → 约定参与方与条款 → 逐条履约（相关参与方成就点 +10）
                              ↘ 违约留痕（相关参与方 -15）
```
### 成就点怎么涨（摘要）

| 谁 | 做了什么 | 成就点 |
|----|----------|--------|
| 自己 | 目标达成 | +5 |
| 自己 | 目标放弃 | -5 |
| 见证人（已确认） | 你监督的目标被对方达成 | +3 |
| 自己 | 契约条款履行 | +10 |
| 自己 | 契约违约 | -15 |

**现实奖励**（跑鞋、电影等）写在目标里，靠「兑现」勾选闭环；**成就点**是系统里的信任分，自己做到和监督别人做到都能涨。

## 6. 概念词典

| 名词 | 通俗解释 |
|------|----------|
| **目标** | 对自己的承诺；绑定自我奖励；达成得成就点 |

### 7.1 主要页面

| 页面 | 一句话 |
|------|--------|
| 注册 / 登录 | 用户名 + 密码即可开始；资料可后补 |
| 忘记 / 重置密码 | 绑定邮箱后可找回 |

| 契约 | 与他人的约定与条款 |
| 创建 | 新建目标或契约；支持语音 / 智能填表 |
| 通知 | 进展、见证、关键节点提醒 |
| 我的 | 资料、履约统计、信任分 |
| 承诺 | 轻量一句话（入口较弱） |

### 7.2 目标

| 内容 | 必需 | 说明 |
|------|------|------|
| 标题 | 是 | 要做到什么 |
| 奖励 | 是 | 达成后奖励自己什么 |
| 描述 / 截止日期 / 见证人 | 否 | 越清楚越好 |

状态：`进行中 → 已达成 → 奖励已兑现`，或 `已放弃`。

### 7.3 契约

| | 目标 | 契约 |
|--|------|------|
| 对象 | 自己 | 他人 |
| 动力 | 自我奖励 | 双方约定 |
| 压力 | 自己 / 见证人 | 参与方互相监督 |

### 7.4 账号

- 注册：用户名 + 密码  
- 资料后补：邮箱、手机、简介  
- 找回密码：依赖已绑定邮箱（试验环境可能直接给出重置链接）  

### 7.5 语音 / AI 创建【当前试验可用】

- 语音 / 智能把一句话拆成表单字段  
- AI 不可用时可手动填写

## 10. 信任分【当前实现口径】

试验版中，信任分出现在首页和「我的」。

| 行为 | 影响 | 谁得分 |
|------|------|--------|
| 目标达成 | +5 | 自己 |
| 目标放弃 | -5 | 自己 |
| 见证的目标达成（已确认见证人） | +3 | 监督他人的见证人 |
| 契约履行相关 | +10 | 自己（参与方） |
| 契约违约相关 | -15 | 自己 |
| 默认 / 范围 | 约从 50 起；约 0～100 | 同一套信任分 |

理解方式：自己达成或监督他人达成都能涨成就点；看长期趋势，不是羞辱工具。

**【规划】更细的分值、等级、权益、连续更新奖励等见第 17 节（全文保留）。** 两套数字暂并存，定稿时再统一。

## 16. 规划：功能模块详述

### 16.1 目标管理（核心）

- 创建目标：标题、描述、奖励、截止日期、进度类型（百分比 / 打卡 / 里程碑）
- 进度追踪：手动更新 / 每日打卡 / 子任务勾选
- 状态流转：进行中 → 已达成 → 已兑现奖励 / 已放弃
- 目标分类：健身、学习、习惯、效率、情感、其他

### 16.2 契约系统（差异化）

- 单人契约：和自己签，条款逐条列出，逐条勾选
- 双人契约：和朋友/伴侣共同签，双方各有负责条款
- 多人契约：最多 5 人，条款分工
- 连坐机制（可选）：一人违约，全员信任分下降
- 契约状态：草稿 → 进行中 → 完成 / 违约 / 取消

### 16.3 承诺（轻量模式）

- 一句话承诺："我这周要跑 3 次步"
- 无条款、无见证人、无押金
- 到期提醒 → 自己标记完成/未完成
- 适合不想走正式流程的轻量场景

### 16.4 通知与提醒（规划加强）

- 进度提醒（每日/每周）
- 截止日期临近提醒
- 见证人邀请通知
- 达成祝贺 / 违约通知
- 见证人验收提醒
- 三端推送：FCM（Android）+ APNs（iOS）+ Web Notification

### 16.5 语音 / AI 创建（规划表述）

- 语音输入：说一句话 → 转文字 → 填入描述
- 智能填写：一句话 → AI 拆分为标题 + 描述 + 建议奖励 + 建议周期
- 降级方案：AI 不可用时回退手动填写

## 17. 规划：信任分扩展规则与等级

| 行为 | 分值（规划稿） |
|------|----------------|
| 目标达成 | +10 |
| 目标放弃 | -10 |
| 契约完成 | +15 |
| 契约违约 | -15 |
| 见证人验收通过 | +3 |
| 连续 7 天更新进度 | +5 |
| 押金模式达成 | +5 |

- 信任分区间对应等级：Lv.1（0–49）→ Lv.5（200+）
- 等级解锁权益：自定义封面、更多见证人名额、专属皮肤、报表导出、专属标识

> 注：与第 10 节【当前实现】分值不同，合并阶段两套均保留，后续统一产品规则。

## 18. 规划：见证、游戏化、模板、海报

### 18.1 见证人系统

- 创建目标/契约时可邀请见证人（最多 3 人，会员 5 人）
- 见证人可查看进度、点赞、留言鼓励
- 可选开启「验收权」：见证人确认后才算达成
- 违约时见证人收到通知（「你见证的 xxx 违约了」）
- 公开目标：设为公开后其他用户可围观、点赞

### 18.2 游戏化

- **积分**：履约、签到、连续更新获得积分
- **虚拟押金**：创建时冻结积分 → 达成双倍返还 → 违约扣除
- **公益捐赠池**：违约扣除的押金进入公益池，累计展示
- **成就徽章**：初出茅庐、早起鸟、阅读狂人、铁人意志、言出必行、最佳拍档、百日不辍、契约大师
- **签到**：每日签到得积分，连续签到加成

### 18.3 模板库

- 预置 20+ 模板（健身/学习/习惯/效率/情感）
- 一键创建：点击模板 → 预填 → 微调 → 创建
- 用户自建模板（会员功能）
- 模板分享到社区

### 18.4 成就海报

- 达成后自动生成分享图片（目标名 + 天数 + 奖励 + 信任分）
- 保存到相册 / 分享到社交平台

## 20. 规划：技术架构与三端场景

### 20.1 技术架构（规划稿原文保留）

| 层 | 选型 |
|----|------|
