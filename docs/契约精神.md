## 1. 开场：我们相信什么

很多人并不缺少目标，缺少的是：**对自己说过的话负责。**

「瘦下来就买包」「项目上线就去旅行」「今年读完二十本书」——话出口时很轻，兑现时却没人记得，最后连自己都不好意思再提。

**契约精神**相信：

- 对自己守信，是对他人守信的起点  
- 奖励不是奢侈，而是履约的燃料  
- 记录不是束缚，而是尊重自己的一种方式  

所以产品英文名是 **SayAndDone——说到，做到。**

---

## 2. 要解决的问题

常见落空不是因为「做不到」，而是因为过程里缺了四样东西：

| 缺口 | 现实里发生的事 |
|------|----------------|
| 没有成本 | 承诺太随意，不当回事 |
| 没有记录 | 说过就忘 |
| 没有追踪 | 达成那天，奖励早忘了 |
| 没有监督 | 没人问一句「你上次说的呢？」 |

我们要提供的，不是又一个待办清单，而是一个让承诺**可记录、可追踪、可兑现、可回顾**的地方。

---

## 3. 产品是什么

**契约精神**是一款以 **目标达成 + 自我奖励** 为核心的承诺管理工具，并支持与他人订立轻量约定。

它填补中间地带：

```
口头承诺          契约精神           正式合同
（太轻、易忘）  ←——————→    （太重、门槛高）
```

用一句话理解使用结果：

| 结果 | 含义 |
|------|------|
| **做到了** | 奖励是你的，系统提醒你去兑现 |
| **没做到** | 不是羞辱，但有据可查——赖不掉 |

**当前形态：** 浏览器即可使用的 Web 产品（试验版）。  
**规划形态：** 同一账号下，Web、Android、iOS 三端互通（见第 15 节）。

## 4. 核心理念

### 四句话

1. **对自己诚实** — 承诺写清楚，不留模糊空间  
2. **用奖励驱动** — 先想清「做到了能得到什么」  
3. **违约有痕迹** — 记录提醒，而非道德审判  
4. **信任看得见** — 履约档案沉淀为信任分  

### 成长路径

```
对自己守信  →  对他人守信  →  建立可感知的社会信任
   （目标）        （契约 / 见证）
```

### 正循环

| 要素 | 作用 |
|------|------|
| 目标 | 明确要做什么 |
| 奖励 | 给兑现一个具体理由 |
| 记录 | 让承诺不易「假装没说过」 |
| 追踪 | 随时看见进度 |
| 兑现 | 完成闭环，强化下次承诺 |

### 产品原则

| 原则 | 含义 |
|------|------|
| 轻量 | 不搞复杂法律条款与正式签署仪式 |
| 真实 | 不为打卡而打卡，强调说到做到 |
| 不装 | 界面与话术直接，少套路 |
| 奖励优先 | 创建目标时，奖励是核心字段 |

视觉气质（便于介绍）：纸感背景、墨色文字、印章红强调——偏「立字为据」，而不是游戏化炫技。

## 5. 两条主线流程

### 主线 A：对自己（最常用）

```
设定目标 → 绑定奖励 → 追踪进度 → 达成 → 兑现奖励
                              ↘ 放弃 → 记录在案（影响信任分）
```

### 主线 B：对他人

```
创建契约 → 约定参与方与条款 → 逐条履约 → 完成 / 违约留痕
```

几乎所有页面，都在服务这两条线。

## 6. 概念词典

| 名词 | 通俗解释 |
|------|----------|
| **目标** | 对自己的承诺，通常绑定奖励 |
| **奖励** | 达成后给自己的回报（创建时强烈建议写清） |
| **兑现** | 真的去拿奖励，并在产品里勾掉「已兑现」 |
| **契约** | 与他人的约定，可拆成多条条款 |
| **条款** | 契约中的一条义务 |
| **承诺** | 更轻的一句话记录（还没想好完整目标时用） |
| **见证人** | 受邀看着你推进的人 |
| **信任分** | 履约与违约沉淀出的守信名片（约 0～100） |

## 7. 功能与页面

### 7.1 你会看到的主要页面

| 页面 | 一句话 |
|------|--------|
| 注册 / 登录 | 用户名 + 密码即可开始；资料可后补 |
| 忘记 / 重置密码 | 绑定邮箱后可找回 |
| 首页 | 信任分 + 进行中事项，像一面镜子 |
| 目标 | 进度、达成、放弃、兑现奖励 |
| 契约 | 与他人的约定与条款 |
| 创建 | 新建目标或契约；支持语音 / 智能填表 |
| 通知 | 进展、见证、关键节点提醒 |
| 我的 | 资料、履约统计、信任分 |
| 承诺 | 轻量一句话（入口较弱，适合进阶了解） |

### 7.2 目标：对自己的契约

| 内容 | 必需 | 说明 |
|------|------|------|
| 标题 | 是 | 要做到什么 |
| 奖励 | 是 | 达成后奖励自己什么 |
| 描述 / 截止日期 / 见证人 | 否 | 越清楚越好 |

状态：`进行中 → 已达成 → 奖励已兑现`，或 `已放弃`。

**例子：** 连续跑步 30 天 → 买一双新跑鞋 → 更新进度 → 达成 → 兑现 → 信任分上升。

### 7.3 契约：对他人的约定

| | 目标 | 契约 |
|--|------|------|
| 对象 | 自己 | 他人 |
| 动力 | 自我奖励 | 双方约定 |
| 压力 | 自己 / 见证人 | 参与方互相监督 |

**例子：** 小红完成设计稿，小李请客——写成契约，条款逐条勾掉。

### 7.4 账号怎么设计

- **注册很轻：** 只要用户名和密码  
- **资料后补：** 邮箱、手机、简介在「我的」里填  
- **找回密码：** 依赖已绑定的邮箱（试验阶段可能直接给出重置链接）  

这是有意为之：先立下承诺身份，再留联系方式。

### 7.5 降低「动笔成本」

创建时支持更自然的输入（语音、智能把一句话拆成表单字段），让「说出来」更容易变成「写下来」。

## 8. 推荐演示路径

讲解或试用时，建议按此顺序（约 5～10 分钟）：

1. 用一句话点题：「你上次答应奖励自己的东西，兑现了吗？」  
2. **注册 / 登录**（强调门槛低）  
3. **首页**看信任分  
4. **创建**一个带奖励的目标（例如：读完一本书 → 看一场电影）  
5. 把进度拉满 → **达成** → **兑现奖励**  
6. 打开 **我的**，看统计变化  
7. （可选）建一份两人契约，或加见证人  
8. （可选）绑定邮箱，演示忘记密码  

收束：**从对自己守信，到对他人守信。**

## 9. 怎么用（操作说明）

### 开始

1. 打开产品（本地演示一般为 http://localhost:3000）  
2. 注册用户名与密码并登录  

### 完成一个目标

1. **创建** → 目标  
2. 写清做什么、奖励是什么  
3. 在 **目标** 更新进度并达成  
4. 现实中兑现后，标记 **奖励已兑现**  

### 立一份契约

1. **创建** → 契约  
2. 填写约定与参与方  
3. 在详情里更新条款状态  

### 绑定邮箱与找回密码

1. **我的** → 保存邮箱  
2. 登录页 → 忘记密码 → 按提示重置

## 10. 信任分

信任分是你的「守信名片」，出现在首页和「我的」。

| 行为 | 大致影响 |
|------|----------|
| 完成目标、履行契约 | 加分 |
| 放弃目标、违约 | 减分 |
| 分数范围 | 约 0～100；新用户通常从中间分起步 |

请这样理解它：

- **看长期趋势**，不要纠结一次涨跌  
- **不是羞辱工具**，而是提醒：你说过的话，还在

## 11. 现在做到哪了

面向介绍场合，用「能不能用」而不是技术名词：

| 能力 | 状态 |
|------|------|
| 目标 + 奖励 + 进度 + 兑现 | ✅ 可用 |
| 契约与条款 | ✅ 可用 |
| 信任分与个人统计 | ✅ 可用 |
| 见证人、站内通知 | ✅ 可用 |
| 低门槛注册、资料后补 | ✅ 可用 |
| 邮箱找回密码 | ✅ 试验可用（正式发信待上线阶段完善） |
| 语音 / 智能创建 | ✅ 试验可用 |
| 公网正式运营、三端 App | 🌱 规划中 |
| 介绍用 PPT / 界面截图册 | ⏳ 本文定稿后补充 |

**一句话现状：**  
核心故事（对自己立目标并兑现）已经能完整演示；距离「正式上架、三端互通」还有产品化与工程化路程。

## 12. 给谁用、有什么价值

| 人群 | 典型场景 |
|------|----------|
| 个人 | 学习、健身、阅读、存钱等自我承诺 |
| 朋友 / 伴侣 | 共同目标、轻量约定 |
| 自由职业者 | 与客户的简单合作约定 |
| 小团队 | 分工与截止承诺（非法律合同） |

| 价值 | 说明 |
|------|------|
| 记录 | 口头承诺落成文字 |
| 追踪 | 进度与状态一目了然 |
| 量化 | 信任分让守信可见 |
| 闭环 | 强迫「奖励」被想清楚、被兑现 |
| 低成本 | 比正式合同轻，比随口一说可靠 |

商业化（免费额度、会员等）可在正式运营阶段再定，**本文不作商务承诺。**

## 13. 和其他工具差在哪

| | 契约精神 | 待办清单 | 电子签约 |
|--|----------|----------|----------|
| 核心问题 | 我说到做到了吗？ | 今天做什么？ | 法律上有效吗？ |
| 奖励 | 产品核心 | 通常没有 | 通常没有 |
| 信任档案 | 有 | 无 | 无 |
| 学习成本 | 低 | 低 | 偏高 |

- 相对待办：不是任务打勾，而是**承诺与兑现**  
- 相对电子签：不是法律效力，而是**日常约定好用**  
- 相对万能笔记：不用从空白页搭结构，**开箱即用**  

```
                正式 / 法律
                     │
              电子签约 ●
                     │
   个人 ─────────────┼───────────── 组织
                     │
          契约精神 ● │
                     │
              待办清单 ●
                     │
                轻量 / 日常
```

## 15. 产品愿景与演进方向

### 愿景（长期）

| 层面 | 方向 |

```

        ↓
② 生产化：稳定账号、正式服务、Web 可公网使用
```

## 17. 常见问题

**一定要填邮箱才能注册吗？**  
不用。登录后在「我的」绑定即可。

**忘记密码？**  
先绑定邮箱，再用登录页「忘记密码」。

**目标和契约？**  
目标对自己、常带奖励；契约对他人、条款履约。

**承诺和目标？**  
承诺是轻量一句话；目标带奖励与完整闭环。

**放弃会被骂吗？**  
不会。会留记录、可能影响信任分，并鼓励重新设定。

**有法律效力吗？**  
没有。请当约定与习惯工具使用。

**现在有手机 App 吗？**  
正式 Android / iOS 仍在规划；当前以 Web 演示为主。

**数据安全？**  
试验阶段多为本地 / 自建部署；正式上线前会配套隐私说明与更完善的账号安全。以届时公示为准。
