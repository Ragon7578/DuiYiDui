# 产品角色与双套结构

> **方向：** 按用户角色拆成两套体验与（最终）两套数据域，而不是「单用户自嗨」。  
> **本阶段：** 先定文档与导航；路由与表结构仍兼容现有 Goal / Contract。

---

## 1. 两个角色（产品入口）

| 角色 | 导航名 | 含义 | 当前落地（过渡） |
|------|--------|------|------------------|
| **对自己** | **我的** | 给自己立承诺、绑奖励、做到了去兑现 | `/goals`、创建「我的」 |
| **监督他人** | **监督** | 与他人约定、见证别人说到做到（多用户） | `/contracts` + 见证人路径将迁入 |

产品不是只有一个用户：监督侧必然涉及**至少两名账号**（承诺方 / 监督方或见证人）。

```
兑一兑
├── 我的（Self）     —— 我对自己的承诺与兑奖
└── 监督（Supervise）—— 我盯别人的承诺；别人也可盯我
```

---

## 2. 导航结构（本阶段）

登录后主导航：

**首页 · 我的 · 监督 · 创建**

| 项 | 路由 | 说明 |
|----|------|------|
| 首页 | `/` | 欢迎页；登录后摘要可分「我的 / 监督」两块（后续） |
| 我的 | `/goals` | 过渡路由名；文案与列表按 Self 域展示 |
| 监督 | `/contracts` | 过渡路由名；文案按 Supervise 域展示 |
| 创建 | `/create` | 先选角色：`?set=self` \| `?set=supervise` |
| 账号 / 通知 / 登出 | 头像菜单 | 不变 |

未登录：主导航仅首页。

---

## 3. 两套数据域（已拆物理表）

| 层 | Self（我的） | Supervise（监督） |
|----|--------------|-------------------|
| **概念** | 自我承诺 + 奖励兑现 | 多方约定、见证、催履约 |
| **导航 / 地图** | 我的列表、兑奖、进度 | 监督列表、待确认见证、履约核对 |
| **物理表** | `self_commitments` | `supervise_agreements` + `parties` + `clauses`；`supervise_witnesses` |
| **API（过渡）** | `/api/goals` | `/api/contracts`（后续可改 `/api/self` · `/api/supervise`） |
| **信任分** | 自己达成 / 放弃 | 监督有效、对方履约/违约相关 |

约束：参与方与见证人必须是**真实 `users` 行**。详见 [data-model.md](./data-model.md)。

---

## 4. 与旧名词对照

| 旧说法 | 新说法（优先） |
|--------|----------------|
| 目标列表 | 我的 |
| 契约列表 | 监督 |
| 创建目标 | 创建 · 我的承诺 |
| 创建契约 | 创建 · 监督约定 |
| 见证人 | 监督侧角色之一（后续从「挂在目标下」收到监督域） |

工程包名可仍为 `@contract-spirit/*`；**对外与导航一律用角色语言**。
