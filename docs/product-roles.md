# 产品角色与双套结构

> **方向：** 按角色拆成两套体验与两套数据域——**给自己的项目** vs **给别人的项目**，而不是单用户自嗨。  
> **本阶段：** 文档、导航、创建页选角、他人解锁门禁已落地；路由与表结构仍兼容现有 Goal / Contract。  
> **后续：** 每角色独立**成长条**（含设置项），见 §5。  
> **体验细则：** [design.md](./design.md)（含市场对照与解锁 UX）。

**市场一句话：** 问责类产品里，社交监督摩擦高、惩罚型劝退温和用户；兑一兑用「先自证履约 → 再解锁盯他人」降低空账号乱监督，并与 stickK / Habitica 的「一上来就社交 / 连坐」拉开差距。

---

## 1. 两个角色（产品入口）

| 角色 | 导航名 | 项目语义 | 含义 | 当前落地（过渡） |
|------|--------|----------|------|------------------|
| **对自己** | **我的** | 给自己的项目 | 给自己立承诺、绑奖励、做到了去兑现 | `/goals`、创建 `?set=self` |
| **对他人** | **他人** | 给别人的项目 | 与他人约定、见证别人说到做到（多用户） | `/contracts`、创建 `?set=others` |

产品不是只有一个用户：他人侧必然涉及**至少两名账号**（承诺方 / 对方或见证人）。

```
兑一兑
├── 我的（Self）      —— 给自己的项目：承诺与兑奖
└── 他人（Others）    —— 给别人的项目：约定 / 见证 / 履约
```

工程内部仍称 Self / Supervise；**对外与导航一律用「我的 / 他人」**。

---

## 2. 导航结构（本阶段）

登录后主导航：

**首页 · 我的 · 他人 · 创建**

| 项 | 路由 | 说明 |
|----|------|------|
| 首页 | `/` | 欢迎页；登录后摘要分「我的 / 他人」两块 |
| 我的 | `/goals` | 给自己的项目列表 |
| 他人 | `/contracts` | 给别人的项目列表；**默认锁定**，见 §2.1 |
| 创建 | `/create` | **须先选角色**；无 `?set=` 时展示选角页 |
| 账号 / 通知 / 登出 | 头像菜单 | 不变 |

未登录：主导航仅首页。

### 2.1 他人角色解锁（已实现）

**规则：** 须先**达成** `3` 个给自己的项目（`achieved_goals` 计数），再**申请解锁**他人角色。

| 状态 | 行为 |
|------|------|
| 未解锁 | 「他人」导航可见但带锁；创建页他人卡片禁用；不能 `POST /api/contracts` |
| 可解锁 | 达成数 ≥ 3 且未解锁 → `/contracts` 或创建页展示「申请解锁」 |
| 已解锁 | 可创建他人项目；`supervise_unlocked_at` 写入用户表 |

已有历史约定的老用户：迁移时若 `total_contracts > 0` 或已达成 ≥ 3，自动视为已解锁。

API：`POST /api/profile/unlock-supervise`；`UserProfile` 含 `superviseUnlocked` / `superviseUnlockProgress` 等字段。

### 创建页选角

| URL 参数 | 角色 | 表单 |
|----------|------|------|
| `?set=self` | 我的 | 自我承诺（奖励必填） |
| `?set=others` | 他人 | 多方约定（须真实用户） |
| 无 `set` | — | 两张选角卡片，点选后写入 URL |

兼容旧参数：`supervise` / `contract` → 他人；`goal` → 我的。

## 3. 两套数据域（已拆物理表）

| 层 | Self（我的） | Others（他人） |
|----|--------------|----------------|
| **概念** | 自我承诺 + 奖励兑现 | 多方约定、见证、催履约 |
| **导航 / 地图** | 我的列表、兑奖、进度 | 他人列表、待确认见证、履约核对 |
| **物理表** | `self_commitments` | `supervise_agreements` + `supervise_parties` + `supervise_clauses`；`supervise_witnesses` |
| **API（过渡）** | `/api/goals` | `/api/contracts` |
| **信任分** | 自己达成 / 放弃 | 对方履约/违约、见证有效相关 |

约束：参与方与见证人必须是**真实 `users` 行**。详见 [data-model.md](./data-model.md)。

| 旧说法 | 新说法（优先） |
|--------|----------------|
| 目标列表 | 我的 · 给自己的项目 |
| 契约列表 / 监督 | 他人 · 给别人的项目 |
| 创建目标 | 创建 · 给自己的项目 |
| 创建契约 / 监督约定 | 创建 · 给别人的项目 |
| 见证人 | 他人侧角色之一（后续从「挂在目标下」收到他人域） |

## 5. 成长条（规划 · 未实现）

每个角色拥有**独立的成长条**，与另一角色分开累计、分开展示。

| 角色 | 成长条含义（初稿） | 主要输入信号（初稿） | 设置项（初稿） |
|------|-------------------|----------------------|----------------|
| **我的** | 自我履约与兑奖习惯 | 达成数、兑奖率、进行中活跃度 | 可见性、提醒节奏、是否展示在首页 |
| **他人** | 见证与督促的有效参与 | 有效见证、约定履约贡献（解锁后） | 通知范围、默认见证偏好 |

**与市场激励的边界：**

- 成长条提供**进度感**（对标习惯 App 的 streak 心理），但**不以断连击羞辱**为默认。  
- **不替代**信任分：信任分 = 履约档案；成长条 = 角色维度长期壳层。  
- **不做**积分商城兑换（终极版议题）；初版最多只读进度 + 设置。  
- 他人成长条在**解锁前**可显示为灰态 / 「解锁后开启」，避免误导。

实现前仅在首页 / 角色列表预留占位，不挡快速上线。
